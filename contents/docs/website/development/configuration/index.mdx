# Configuration Files - Edukai Frontend ⚙️

## Overview

The Edukai frontend uses multiple configuration files to set up the development environment, build process, styling, and type checking. Each configuration file serves a specific purpose in the application architecture.

## Configuration Files Structure

```
📁 Root Configuration Files
├── 📄 package.json              # Dependencies and scripts
├── 📄 tailwind.config.ts        # Tailwind CSS configuration
├── 📄 tsconfig.json             # TypeScript configuration
├── 📄 next.config.mjs           # Next.js configuration
├── 📄 components.json           # ShadCN UI configuration
├── 📄 postcss.config.mjs        # PostCSS configuration
├── 📄 .gitignore                # Git ignore patterns
├── 📄 Dockerfile                # Docker container configuration
├── 📄 pnpm-lock.yaml           # PNPM lock file
└── 📄 package-lock.json         # NPM lock file
```

## TypeScript Configuration (`tsconfig.json`)

### Configuration Overview

```json
{
  "compilerOptions": {
    "lib": ["dom", "dom.iterable", "es6"],
    "allowJs": true,
    "skipLibCheck": true,
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "module": "esnext",
    "moduleResolution": "bundler",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "jsx": "preserve",
    "incremental": true,
    "plugins": [
      {
        "name": "next"
      }
    ],
    "paths": {
      "@/*": ["./*"]
    }
  },
  "include": ["next-env.d.ts", "**/*.ts", "**/*.tsx", ".next/types/**/*.ts"],
  "exclude": ["node_modules"]
}
```

### Key Configuration Explanations

#### **Strict Type Checking**

- `"strict": true` - Enables all strict type checking options
- `"noEmit": true` - Only type check, don't emit JavaScript
- `"skipLibCheck": true` - Skip type checking of declaration files

#### **Module Resolution**

- `"moduleResolution": "bundler"` - Use bundler-style resolution
- `"esModuleInterop": true` - Enable ES module interoperability
- `"isolatedModules": true` - Ensure each file is a module

#### **Path Mapping**

```json
{
  "paths": {
    "@/*": ["./*"] // Absolute imports from root
  }
}
```

Enables clean imports:

```typescript
import { Button } from "@/components/ui/button";
import { useAuth } from "@/hooks/useAuth";
```

## Docker Configuration (`Dockerfile`)

### Container Setup

```dockerfile
FROM node:18-alpine AS base

# Install dependencies only when needed
FROM base AS deps
RUN apk add --no-cache libc6-compat
WORKDIR /app

COPY package.json yarn.lock* package-lock.json* pnpm-lock.yaml* ./
RUN \
  if [ -f yarn.lock ]; then yarn --frozen-lockfile; \
  elif [ -f package-lock.json ]; then npm ci; \
  elif [ -f pnpm-lock.yaml ]; then corepack enable pnpm && pnpm i --frozen-lockfile; \
  else echo "Lockfile not found." && exit 1; \
  fi

# Production build
FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .

RUN npm run build

# Production image
FROM base AS runner
WORKDIR /app

ENV NODE_ENV production

RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000

ENV PORT 3000

CMD ["node", "server.js"]
```

## Environment Configuration

### Environment Variables Structure

```bash
# .env.local (development)
NEXT_PUBLIC_API_URL=http://localhost:3001
NEXT_PUBLIC_AUTH_COOKIE_NAME=auth_token
NEXT_PUBLIC_AUTH_COOKIE_DOMAIN=localhost

# .env.production (production)
NEXT_PUBLIC_API_URL=https://api.edukai.com
NEXT_PUBLIC_AUTH_COOKIE_NAME=auth_token
NEXT_PUBLIC_AUTH_COOKIE_DOMAIN=.edukai.com
```

### Environment Variable Categories

#### **Public Variables** (Available in browser)

- `NEXT_PUBLIC_API_URL` - Backend API URL
- `NEXT_PUBLIC_AUTH_COOKIE_NAME` - Authentication cookie name
- `NEXT_PUBLIC_AUTH_COOKIE_DOMAIN` - Cookie domain

#### **Server-only Variables**

- `DATABASE_URL` - Database connection string
- `JWT_SECRET` - JWT signing secret
- `API_SECRET_KEY` - API authentication key

## Configuration Best Practices

### 1. **Environment-Specific Configuration**

```typescript
// lib/config.ts
export const config = {
  apiUrl: process.env.NEXT_PUBLIC_API_URL || "http://localhost:3001",
  isDevelopment: process.env.NODE_ENV === "development",
  isProduction: process.env.NODE_ENV === "production",
};
```

### 2. **Type-Safe Configuration**

```typescript
// lib/env.ts
import { z } from "zod";

const envSchema = z.object({
  NEXT_PUBLIC_API_URL: z.string().url(),
  NEXT_PUBLIC_AUTH_COOKIE_NAME: z.string(),
  NODE_ENV: z.enum(["development", "test", "production"]),
});

export const env = envSchema.parse(process.env);
```

### 3. **Feature Flags**

```typescript
// lib/features.ts
export const features = {
  enableNewDashboard: process.env.NEXT_PUBLIC_ENABLE_NEW_DASHBOARD === "true",
  enableAnalytics: process.env.NEXT_PUBLIC_ENABLE_ANALYTICS === "true",
  enableBetaFeatures: process.env.NODE_ENV === "development",
};
```
